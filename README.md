# COLORS

A COP 4331 LAMP lab application for logging in, adding colors, and searching saved colors. Built from the course-provided starter code.

**Lab site:** https://snoel.dev (may be repurposed after grading).

## Technologies

HTML, CSS, JavaScript, PHP, MySQL, and Apache on an Ubuntu DigitalOcean droplet. HTTPS uses Let's Encrypt/Certbot, with DNS managed through Cloudflare.

## Project Structure

- `index.html` and `color.html`: login and color management pages.
- `LAMPAPI/`: PHP endpoints for login, adding colors, and searching colors.
- `css/`, `js/`, and `images/`: frontend styles, scripts, and images.

## Setup

1. Clone this repository and prepare a Linux server with Apache, MySQL, and PHP with mysqli/mysqlnd support.
2. Create the `COP4331` database with these tables:
   - `Users`: `ID`, `FirstName`, `LastName`, `Login`, `Password`.
   - `Colors`: `ID`, `Name`, `UserID`.
   - `Contacts`: `ID`, `FirstName`, `LastName`, `Phone`, `Email`, `UserID` (unused by COLORS).

   Each `ID` is an auto-increment integer primary key; `UserID` is an integer and text fields are `VARCHAR(50)`. Add a test user and associate color rows with that user's ID.
3. Create a local MySQL application account with data read/write permissions on `COP4331`.
4. Create `/etc/colors/database.php` on the server. It must return a PHP array containing `host`, `username`, `password`, and `database`. Use your database account credentials and allow the Apache user to read the file. Keep this file outside Git and the web root.
5. Copy the HTML files and `LAMPAPI/`, `css/`, `js/`, and `images/` into `/var/www/html`. Keep the directory structure intact and exclude private files and `.git`.
6. Point your domain to the server and configure HTTPS. The frontend calls `/LAMPAPI` on the same domain.

## Running the App

With Apache and MySQL running, open the site's URL in a browser. Log in with the application account created during setup, add a color, and search by part or all of its name. Use **Log Out** to end the session. Opening the HTML files directly will not run the PHP backend.

Manual testing covered valid and invalid login, adding and searching colors, persistence after reopening the site, and HTTPS.

## Limitations

This is a lab demonstration. Passwords are compared directly, and color endpoints trust the supplied user ID rather than checking a server-side session. Input validation and output encoding are limited. Accounts must be created in MySQL; there is no registration page. The included MD5 demonstration is inactive. These authentication and password-storage practices are not suitable for production.
